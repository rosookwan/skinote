# 둘째 판 화면 채택 기록

작성 2026-09-24. 둘째 판 화면 아홉 장은 후보가 둘씩이다: 검토를 거친 **코드 시안**(`vN-*.html` · `.png`, `measure.mjs`로 잼, 검토에서 찾은 73곳을 고침)과 **힉스필드 그림**(`higgsfield/*.jpg`, `higgsfield/results.json`). 힉스필드 그림은 검토 **전**의 첫 설명서로 뽑은 것이라 문구 · 구조가 옛것이지만, 화면의 무게 배분은 더 나은 곳이 있다. 이 문서는 화면마다 무엇을 채택했고 힉스필드 그림에서 무엇을 옮겼는지(접붙임), 두 그림이 어디서 다르고 왜 코드 시안이 맞는지를 적는다.

**첫 매장 답(2026-09-26, 채택 뒤).** 첫 매장은 장비 · 리프트권에 번호가 없고 손님 보증금이 없다(README D7). 채택은 그대로이고 시안은 다시 그리지 않는다. 첫 매장이 쓰는 모양(수량 −/+ 칸, 보증금 줄 없음)은 9절이다.

**문구(2026-09-24, 채택 뒤).** 사용자 요청으로 코드 시안의 화면 문구를 [문구 표](../wording.md)의 짧은 시스템 말로 바꿨다(대화형 말 · `약속` 없앰, 배치 · 크기 그대로, 8절). 이 기록에서 **코드 시안을 인용한 글은 새 말**이고, **힉스필드 그림을 인용한 글은 그림 속 옛 말 그대로**다. 힉스필드 그림은 다시 뽑지 않았다(크레딧 0).

## 1. 채택 규칙

1. **아홉 장 모두 채택 = 코드 시안.** 명세(`spec.md`)의 문구 · 예시 숫자 · 도메인 규칙을 따르고, 앱과 같은 토큰 · 부품 · 글꼴로 그렸으며, 검사기가 글자 16px · 누르는 곳(포스 52 · 기사 56) · 확인 창 크기(`confirmWindow`) · 작은 틀(1024×569 · 1024×529 · 기사 1024×520)을 잰다.
2. **힉스필드 그림은 채택하지 않는다.** 대신 그림이 분명히 나은 **모양**(크기 · 여백 · 꽉 찬 배치 · 그림 기호)만 코드 시안에 옮긴다. 문구와 도메인 동작(무엇을 누르면 무엇이 되는지, 어떤 줄이 언제 보이는지)은 바꾸지 않는다.
3. 옮긴 뒤에도 `node docs/design/screens-v2/measure.mjs`가 모든 화면 · 상태 변형 · 작은 틀에서 통과해야 한다(6절).
4. **다시 뽑지 않는다.** 예시 자료의 글자 오타(`내솔동`)나 옛 문구는 기록만 한다(크레딧, spec.md 0절 4). 이번 채택에서 쓴 크레딧은 0이다.

`higgsfield/results.json`의 화면마다 `"adopted": false`와 `"graftedInto"`(옮긴 코드 시안과 모양, 옮긴 것이 없으면 `null`과 `adoptionNote`)를 적었다. 모아 보기 `index.html`은 화면마다 채택 한 줄과 힉스필드 그림(첫 설명서 기준)을 함께 보인다.

## 3. 반납 · 일정

### V1 반납 확인 창 · 부분 반납

- **채택**: 코드 시안(`v1-partial-return.html`).
- **옮긴 것**: 힉스필드 그림은 품목 이름이 크고 칸 사이가 넉넉하다. 품목 이름을 20 → 22px로, 두 칸 사이를 16 → 24, 칸 안 왼쪽 여백을 8 → 12, 번호 버튼 폭을 약 60 → 64로 넓혔다. 창은 그대로 860 × 440이다.
- **옮기지 않은 것**: 세로 여유. 이 창은 1024×529(설치한 앱)의 창 한도 505 안에서 품목 줄 6개(② 세 줄, 창 500)까지 한 쪽이어야 한다(명세 3-1). 남는 세로 여유가 5px이라 줄 높이 · 줄 사이를 늘리면 줄 6개 팀이 쪽을 넘긴다. 그래서 여유는 가로로만 주었다.
- **두 그림의 차이와 코드 시안이 맞는 까닭**
  - 그림에는 `모두 반납 · 6개 · 3매` / `일부만` 고르기가 있다. 검토에서 없앴다: 급할 때 기본값(모두)을 세지 않고 누르면 숙소에 있는 보드까지 반납되고 두솔동 수거가 사라진다. 코드 시안은 품목 칸이 늘 보이고 처음에 모두 골라져 있다.
  - 그림은 품목마다 −/+ 수량과 `2대 중`이다. 스키 · 보드 · 헬멧 · 리프트권은 하나씩 세는 품목이라 돌아온 **번호**를 눌러야 권마다 다시 전달 · 발권처 환불이 된다(ui 3-1, data-model 4-9). `N개 중`은 헬멧 규격 `중`과 헷갈려 쓰지 않는다. (2026-09-26: 첫 매장은 번호가 없어 모든 줄이 −/+ 수량이다 — 9절. 그래도 그림의 `모두 반납` / `일부만` 고르기와 `2대 중`은 받지 않고, 코드 시안의 '처음에 모두 골라 둠'과 고글 칸의 수량 모양을 쓴다.)
  - 그림의 `현금으로 돌려드림`은 동작처럼 읽힌다. 코드 시안은 이름표 `반환 방법` + 이름씨 버튼 `현금` · `미수 차감 · 120,000원 → 110,000원`(V4 수단 버튼과 같은 모양)이다.
  - 그림의 주 버튼에는 돌려드릴 보증금이 없다. 코드 시안은 `반납 처리 · 스키 2 · 헬멧 2 · 권 2매 · 보증금 10,000원`으로 돈통이 열리는 까닭까지 적는다.
  - 그림의 남는 것 줄에는 설천 주차장 수거가 필요 없어진다는 표시(코드 시안 `설천 주차장 수거 취소`)가 없고, 보증금 줄에 잔여 보증금(코드 시안 `잔여 보증금 5,000원(권 1매)`)이 없다.
  - 그림의 창 폭은 약 520px(1024 기준)이다. 확인 창 폭은 `confirmWindow()`로 860이다.
- **results.json 기록**: 뒤 접수증의 대표자 칸이 빠지고 돈 줄이 두 줄로 그려짐(흐린 배경이라 기록만, 다시 뽑지 않음).

### V9 일정 변경 · 부분 품목

- **채택**: 코드 시안(`v9-change-promise.html`).
- **옮긴 것**: 없음. 창이 1024×529 한도 505 중 약 503을 써서 칸을 키울 여유가 없고, 그림에서 넉넉해 보이는 까닭은 창 폭이 좁고(약 567px) 줄이 작기 때문이다.
- **두 그림의 차이와 코드 시안이 맞는 까닭**
  - 그림은 `받는 사람` 줄(`매장으로 가져옴` · `차량이 받음 · 1호 차량` · `차량이 받음 · 2호 차량`)을 둔다. 검토에서 없앴다: `매장으로 가져옴`과 `매장 직접`이 서로를 몰래 바꾸는 한 쌍이었다. 코드 시안은 `매장 직접` = 손님이 가져옴, 차량 구역 = `수거 차량` 줄(`매장 직접`이면 자리만)이다.
  - 그림은 고른 구역의 장소를 따로 한 줄(`한솔동` · `두솔동` · `세솔동` · `내솔동` · `직접 입력`)로 둔다. 코드 시안은 장소를 고르면 구역 버튼이 두 줄 `솔마을` / `두솔동`이 되어 줄 수가 늘지 않는다(그래서 1024×529에 들어감).
  - 그림의 구역 순서(`만선` · `설천` · `꽃마을` · `솔마을`)는 체험 자료 순서(`설천` · `만선` · `솔마을` · `꽃마을`)와 다르다.
  - 그림의 반납 시각 `오전타임 12:00` · `날짜`는 사장님 말 `오전타임 후 12:00` · `다른 날 ›`과 다르고, 오늘 지난 타임이 회색 점선이 아니다.
  - 그림은 `2대 중`(헬멧 규격 `중`과 헷갈림), 코드 시안은 `대여 2대`.
  - 그림의 요약은 한 줄 `… · 나머지는 그대로`, 코드 시안은 `변경` · `유지` 두 줄로 남는 일정도 적는다.
- **results.json 기록**: `네솔동`이 `내솔동`으로 그려짐(샘플 이름 오탈자, 기록만 · 다시 뽑지 않음).

## 4. 새 접수 · 수납

### V4 접수 확정 창 · 칸별 수납

- **채택**: 코드 시안(`v4-confirm-payment.html`).
- **옮긴 것**: 없음. 그림은 수단 버튼이 칸 폭을 채우지만, 코드 시안은 수단 버튼 다섯(각 110) 뒤에 틈을 두고 `할인 적용 ›`을 끝에 떼어 두어 수단 선택과 할인 적용이 갈린다. 채우면 그 틈이 사라진다.
- **두 그림의 차이와 코드 시안이 맞는 까닭**
  - 그림의 창 폭은 약 624px이다. 확인 창 폭은 `confirmWindow()`로 860이다.
  - 그림의 주 버튼 `수납하고 접수 확정 · 160,000원`: 보증금은 수납이 아니다(data-model 4-12). 코드 시안은 `접수 확정 · 현금 160,000원`으로 카드 단말에 칠 돈과 돈통에 넣을 돈을 가르고, `받을 금액 현금 160,000원 = 리프트권 140,000원 + 보증금 20,000원` 줄이 있다(그림에는 없음).
  - 그림의 보증금 칸에는 수단 버튼 넷이 있다. 이 매장은 보증금을 현금으로만 받아(명세 2-3) 버튼 없는 한 줄 52이다.
  - 그림의 리프트권 칸에 `이 매장은 선입금 전액`: 선입금은 전화 예약에만 걸린다(catalog 11). 이민호 팀은 현장 접수다.
  - 그림은 칸 제목 줄에 `할인 없음 ›` 버튼, 결제할 팀에 `이 팀`이다. 코드 시안은 회색 `할인 없음` + 수단 줄 끝 `할인 적용 ›`, 결제 팀은 `이민호 · 0042`(`이 팀`은 옆 `이정호`와 붙어 '이 씨 팀'으로 읽힘)이고, 후불인 장비 칸에 파란 `이정호 팀 결제 예정`과 옅은 금액이 있다.
- **results.json 기록**: 흐린 뒤 화면의 새 접수 내용이 요청과 조금 다름(기록만).

  - **지금 연 종류**: 그림은 남색 바탕이라 한눈에 보인다. 남색 바탕은 '고름'의 모양이라(명세 3-4) 그대로 옮기지 않고, 옅은 바탕은 그대로 두고 테두리를 3 → 4px로 굵게 하고 수 표시 앞에 아래 갈매기 그림(`icons.tsx`의 `down`)을 붙여 '이 종류의 줄이 아래에 열려 있음'을 또렷하게 했다.
- **두 그림의 차이와 코드 시안이 맞는 까닭**
  - 그림의 단계 탭 `③ 확인`: `확인`은 '끝났다'로 읽히고 머리줄 `확인 필요`와 헷갈려 `③ 확정`으로 바꿨다(문구 표 뒤 `③ 결제`).
  - 그림의 둘째 고르는 줄 `100 수량`은 '수량 100'으로 읽힌다. 코드 시안은 `사이즈 100`.
  - 그림의 합계에 `보증금 20,000원 · 돌려드림`: 받는 이 자리는 `보증금 · 별도`이고 반환 말(`반납 시 반환`)은 V4 · V1에만 쓴다. 보증금은 합계에 넣지 않는다.
  - 그림의 리프트권 타일은 4매를 골랐는데도 `권종 고르기`다. 고른 뒤에는 `야간권 35,000원`(고른 권종과 1매 값).
  - 그림의 고른 것 둘째 줄 `어른` · `중`은 코드 시안에서 `부츠 · 폴 포함` · `중 사이즈`(규격을 이름과 함께).
- **results.json 기록**: 통과, 문구 · 배치 요청대로(첫 설명서 기준).

### V3 새 접수 ② 일정

- **채택**: 코드 시안(`v3-new-order-promise.html`).
- **옮긴 것**: 없음. 그림의 묶음 사이 가는 선은 보기 좋지만 코드 시안의 회색 제목 줄이 같은 일을 하고, 차이가 작다.
- **두 그림의 차이와 코드 시안이 맞는 까닭**
  - 그림은 리프트권 권종 · 매수 줄(`오전권` … `종일권` · `− 4매 +`)을 둔다. 권종 · 매수는 V2에서만 고른다(같은 권 줄을 두 곳에서 고치지 않게, ADR-05).
  - 그림의 `받는 방법` / `매장에서 바로 · 지금` · 오른쪽 판 `받기`: `받기`는 기사 화면의 수거(옛 말 `받음`)와 헷갈린다. 코드 시안은 장부와 같은 `수령` · `반납`, 매장에서 하는 것은 `매장 직접`.
  - 그림에는 `예약 · 수령일 ›`과 따로 된 `반납 날` 줄이 없고 `내일` · `날짜`가 시각 줄에 섞여 있다. 코드 시안은 날(`오늘` · `내일` · `다른 날 ›`)과 시각을 다른 줄로 두어 `내일` → `오전타임 후 12:00`처럼 고른다.

## 8. 문구 변경(2026-09-24)

채택 뒤 사용자가 대화형 문구(`할인 고르기` · `받을 돈 정하기` · `약속 정하기` · `약속 바꾸기` …)를 실제 시스템 말로 바꾸길 원했다. 글만 바꾸고 배치 · 크기 · 도메인 동작은 그대로다. 말은 모두 [문구 표](../wording.md)에서 가져왔다.

- **아홉 장의 글 · `aria-label` · `<title>`**: 예) `반납 도장 찍기 · …` → `반납 처리 · …`, `돌려드리는 방법` → `반환 방법`, `약속 바꾸기` → `일정 변경`, `② 약속` · `③ 확정` → `② 일정` · `③ 결제`, `돈 받고 접수 확정 · …` → `접수 확정 · …`, `나중에` · `다른 수단` → `후불` · `기타`, `한 번에 수납` → `일괄 수납`, `셀 돈` → `현금 점검`, `마감하기` → `마감`, `전달 도장 · 6개` → `배달 처리 · 6개`, `가게 규칙` → `운영 규칙`, `보증금 안 돌려드림` → `보증금 몰수`, `전날 장부로 치는 시각` → `영업일 기준 시각`.
- **`spec.json`**: 화면 이름(`title`) · 주 버튼(`primary`) · 꼭 보여야 할 글(`mustShow`, 상태 변형 · 작은 틀 포함)과 힉스필드 요청문(`prompt`)의 따옴표 안 화면 글. 새 칸 `wording`에 그림이 이 변경 전의 말이라는 것을 적었다. 창 뒤 화면의 새 말(`수령 16:00 · 매장 · 반납 일정 2건 ›` · `부분 수납` · `일정 변경` · `완료 2건` 등)도 `mustShow`에 더해 검사가 본다.
- **폭**: 새 말은 거의 모두 같거나 짧다. 가장 빠듯한 곳은 V5 `부분 · 165,000원 ›`(버튼 얼굴 148)이고 넘치지 않는다. 문구 표의 짧은 말(`미전송` · `차액 청구`)은 쓸 일이 없었다.
- **힉스필드 그림**: 다시 뽑지 않았다. 그림 속 글(`현금으로 돌려드림` · `받기` · `못 받음` · `보증금에서 뺌` …)은 옛 말이고, 모아 보기 `index.html`은 그림을 '채택하지 않음 · 첫 설명서 기준'으로 보인다.

## 9. 첫 매장 답(2026-09-26)과 채택한 시안

첫 매장 사장님 답(README D7)으로 첫 매장은 **장비 · 리프트권에 번호가 없고**(모든 품목 `count`) **손님 보증금이 없다**(사장님이 말한 1,000원은 스키장 권 값 안의 카드 보증금). 아홉 장은 번호 장비 · 권 보증금이 있는 견본 매장(명세 2-3)으로 그렸고, **다시 그리지 않는다**(코드 시안도 힉스필드 그림도, 크레딧 0). 화면의 틀 · 차례 · 크기 · 주 버튼 자리는 같고, 첫 매장은 같은 화면의 두 모양을 쓴다.

- **수량 −/+ 칸 모양:** 시안에서 고글 칸(`− 6 +`)으로 그린 모양을 모든 품목이 쓴다. 칸 둘째 줄은 번호 칸과 같은 일정별 수(`설천 2 · 두솔동 1`)다(그림의 고글 칸 `대여 6개`를 대신함, ui 6-2). 번호 버튼(`17번` · `18번`)과 `번호 선택 ›`은 첫 매장에 나오지 않는다. 처음에 이 팀이 가진 것을 모두 골라 두는 규칙(D5)은 그대로라 처음 값은 가진 수다.
- **보증금 줄 · 칸 없는 모양:** 설계가 '보증금을 맡지 않는 매장'으로 이미 적어 둔 모양이다(창 높이는 연 동안 그대로, ui 4-5 · 6-2).

| 화면 | 첫 매장에서 달라지는 곳(그림은 그대로) |
|---|---|
| V1 반납 확인 창 | 품목 칸이 모두 −/+. ① 회색 표시는 `전체 선택 · 미반납 수량 감소`(wording.md 3-18, 확인 대기). ④ 보증금 줄 · ⑤ `반환 방법` 없음 → 창 344, 주 버튼 `반납 처리 · 스키 2 · 헬멧 2 · 권 2매` |
