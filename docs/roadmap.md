# 일정과 지금 상태

작성 2026-09-23. 고침 2026-09-24(사장님 답 D1–D5가 들어갈 주는 3절 끝; 같은 날 **배치를 클라우드 중심으로 바꿈** — README ADR-19, [deployment.md](architecture/deployment.md); 같은 날 셋째 검토(끊김 · 보안 · 운영 · 일관성)를 반영해 운영 일을 '개장 필수'와 '두 번째 매장 전에'로 나눔: 1주차 업체 · 스파이크 넷 · 가게 인터넷 측정, 4 · 5주차 서버 · 복제 · F1 준비 · 예비 회선 자동 넘어가기, 6주차 카운터 오프라인 사실과 큐 규칙, 7 · 10주차 새 VM 되살리기; 같은 날 화면 문구를 짧은 업무 용어로 바꾸기로 함 — README D6, [docs/design/wording.md](design/wording.md)). **고침 2026-09-26:** 첫 매장 사장님이 확인 질문지 2차에 답함(README D7) — 3절 '첫 매장 답(2026-09-26)'과 5절. [migration-plan.md 6절](architecture/migration-plan.md#6-10주-계획2026-09-28--12-04)의 10주 계획(2026-09-28 ~ 12-04)에 지금까지 한 것을 겹쳐 적는다. 무엇을 왜 하는지는 migration-plan이 기준이고, 이 문서는 어디까지 왔는지와 주마다 다음에 할 것만 적는다. 한 주가 끝날 때마다 고친다.

줄기는 다섯이다: **기반**(schema · store · domain), **legacy**(codec · facade · 옛 시험), **기능**(N 목록), **화면**(React), **운영**(중앙 서버 · 배포 · 복제 · 감시, 2026-09-24부터; 아래 표에서는 기반 칸에 적음). 화면 줄기는 예시 자료(`FixtureClient`)로 먼저 달려 1주차 전에 2 ~ 4주차 화면의 모양을 거의 갖췄다. 기반 · legacy 줄기는 스키마와 실행기까지 왔다.

## 4. 앞 단계에서 남긴 작은 일

- `ui-defaults.json`은 판 3이다(2026-09-24 화면 문구 변경, README D6). 판 2는 2026-09-23 검토(시각 칸 합침 폭 4em · 반납 일정 칸 최소 10.5em, 수거 목록 팀 칸 비율, 수납 `has_due` · 조기 반납 `has_items_out` 조건). `ui_defaults.apply`가 옛 매장 파일을 이 판으로 올린다.
- 앱에 `새 버전` 표시와 `새 버전 적용` 버튼이 없다. 서비스 워커는 `skinote:apply-update`를 받을 준비가 되어 있다(열린 창이 없고 보냄 대기가 0일 때만 보내기로).
- 휴대폰에서 `시간순 정렬` 버튼이 폭 때문에 동작 줄에서 빠진다(맨 위로도 빠짐). 목록 머리나 더 보기 판에 둘지 정한다.
- 같은 끝 4자리가 여러 팀일 때 고르는 창은 예시 자료에 그런 팀이 없어 규칙 검사기가 열어 보지 못한다.
- 110% · 125% 확대 크기가 DeviceProfile `checkSizes`에 없어 규칙 검사기가 돌지 않는다(ui 8절에는 있음).
- 앞 단계의 `scripts/check-screens.mjs`(`test:ui`)는 이제 DeviceProfile · 토큰을 읽지만 규칙 검사기와 겹친다. 규칙 검사기로 옮겨 없앨지 정한다.
- 수거 목록 인쇄는 알림만 뜨고, `전화`는 번호만 보인다.
- 화면 훅(`useConfirmFlow` · `useLive` · `useCommandDraft`)을 DOM에서 도는 시험이 없다(시험에 DOM 흉내 패키지를 들이지 않았다). 봉투 · 초안의 순수 함수(`confirmEnvelope` · `draftOptions` · `reusableDraft`)와 규칙 검사기의 흐름으로 본다.
- 운영 연결(HttpClient)이 오면 `DomainError`의 NETWORK를 연결 띠와 잇고, 답을 잃은 명령은 `outcome 'unknown'`(결과 확인 중)으로 가르며, `pending()`을 전송 대기 목록 화면에 쓴다. 카운터도 기사처럼 끊기면 LocalClient로 넘어가므로(ADR-19) 체험판의 연결 끊김 흉내(`#/exit?from=driver`)를 카운터 쪽에도 두어 규칙 검사기가 카운터 연결 띠를 재게 한다.
- 카운터 장부의 줄 수 계산에 연결 띠 자리(32px)를 늘 뺀다(ui 4-3, 셋째 검토; 지금 체험판은 1024×600에서 7줄). 사장님 확인(README 열린 질문 31) 뒤에 바꾼다.
- 카운터 PWA가 마감 뒤 · 05:00 ~ 06:00에 스스로 다시 여는 곳(deployment 7절)과 '새 버전' 표시.
- 아직 없는 부품: `MethodRow`, `PlaceChooser`, `SlotChooser`, `ReviewList` · `ReviewBanner` · `ReviewStep`, `ChangeBanner`. 아직 없는 기사 화면(6-5): 배달 목록, 업무 판, 현장 수납 판, 리프트권 추가 판. 아직 없는 카운터 화면: 새 접수 ①②(6-6), 일괄 수납(6-7), 마감(6-8), 운영 규칙(6-9).
- 루트 `engines`는 Node 22.13 이상이지만 `.ts`를 Node로 바로 읽는 검사 스크립트(`check:imports`, 규칙 검사기)는 22.18 이상이 필요하다. CI는 Node 22 최신판을 쓴다.
